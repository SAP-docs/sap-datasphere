# Configuring Workload Identity Federation for Google BigQuery Connections

Configure Workload Identity Federation to let SAP Datasphere replication flows securely access Google BigQuery without using long-lived service account keys. Configuration steps are required in Google Cloud Platform and in SAP Cloud Identity Services Identity Authentication.

## Prerequisites

You require:

-   Administrator access to Google Cloud Platform \(GCP\), including permissions to create or update a Workload Identity Pool and Provider in your GCP project
-   Administrator access to your SAP Cloud Identity Services tenant



<a name="loio7962a49923d84644910b1c6001df0145__context"/>

## Context

Workload Identity Federation eliminates the need to create, rotate, and distribute long-lived Google Cloud Platform service account JSON keys. Instead, the service issues short-lived tokens through a federated identity chain anchored at Identity Authentication in SAP Cloud Identity Services. This improves security, compliance, and operational management.

The required configuration steps involve:



-   Creating a Workload Identity pool and provider in Google Cloud Platform
-   Creating and configuring an OpenID Connect \(OIDC\) Application in Identity Authentication

For more information about Google Workload Identity Federation, see [Workload Identitiy Federation](https://docs.cloud.google.com/iam/docs/workload-identity-federation) in the *Google Cloud* documentation.

## Create and Configure a Workload Identity Pool in Google Cloud Platform

1.  In the Google Cloud console, go to the *Workload Identity Pools* page to create a workload identity pool in the Google Cloud project that you want to connect to via Google BigQuery.

    For more information, see [Manage workload identity pools and providers](https://docs.cloud.google.com/iam/docs/manage-workload-identity-pools-providers) in the *Google Cloud* documentation.

2.  Add a provider of type *OIDC* \(OpenID Connect\) and complete the following properties:

3.  Allow SAP Datasphere replication flows to access Google BigQuery. You have two options to grant BigQuery access:
    -   Direct resource access:

        In the Google Cloud console, go to the *IAM* page to grant the Workload Identity Federation pool principal the *BigQuery Data Viewer* and *BigQuery Job User* IAM roles \(scoped to the relevant datasets if required\). The principal identifier uses the "sub" claim from the token generated by Identity Authentication \(client ID\): <code>principal://iam.googleapis.com/projects/<i class="varname">&lt;Google Cloud project id&gt;</i>/locations/global/workloadIdentityPools/<i class="varname">&lt;pool id&gt;</i>/subject/<i class="varname">&lt;sub value (client id)&gt;</i></code>.

        For more information, see the *Google Cloud* documentation:

        -   [Grant an IAM role](https://docs.cloud.google.com/iam/docs/grant-role-console#grant_an_iam_role)
        -   [BigQuery IAM roles and permissions](https://docs.cloud.google.com/bigquery/docs/access-control)

    -   Alternatively, you can use service account impersonation: Create a GCP service account and grant it the required BigQuery roles. Grant the Workload Identity Federation pool access to the service account to enable impersonation.

        1.  In the Google Cloud console, go to the *Create service account* page to create a service account in the Google Cloud project that you want to connect to via Google BigQuery and grant it the required BigQuery roles.
        2.  Go to the *Workload Identity Pools* page to grant the Workload Identity Federation pool access to the service account to enable impersonation.

        For more information, see the *Google Cloud* documentation:

        -   [Create service accounts](https://docs.cloud.google.com/iam/docs/service-accounts-create)
        -   [Service account impersonation](https://docs.cloud.google.com/iam/docs/workload-identity-federation-with-other-providers#impersonation)

## Results

You have completed the configuration required to obtain short-lived access tokens. You can now create connections using the *Workload Identity Federation* authentication type. For more information, see [Google BigQuery Connections](google-bigquery-connections-30ed77d.md).
